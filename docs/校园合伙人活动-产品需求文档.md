## 1. 文档定位

**项目背景：在已经运行的New API生产项目中新增校园合伙人功能，沿用现有用户账号、登录注册、钱包充值、订阅外部支付及后台权限能力；校园合伙人与旧“邀请好友”活动完全独立，不复用旧活动的邀请码、邀请关系、奖励余额或活动规则。不是新建独立推广平台，也不是重建现有支付系统。**

本文作为校园合伙人活动的产品需求基线，描述用户能做什么、业务如何计量、异常情况下应得到什么结果及验收标准。开发团队据此独立设计实现，不要求复用原交付中的源码、HTML、算法、接口、组件或数据结构。

本文已按用户逐项确认的结论形成开发基线，第10节保留决策记录供追溯。原交付材料与本文不一致时，以本文及用户后续确认的变更为准。实际套餐标识、已启用支付渠道、现有权限及接口接入点由开发核实，不属于尚待用户决定的业务规则。

原稿中的用户、金额、邀请码、域名和日期均为演示数据，不能作为生产数据或财务验收样本。

## 2. 目标与范围

### 2.1 产品目标

在现有科研 API 站点中提供邀请推广活动：用户邀请好友注册和消费，好友获得充值优惠，邀请人获得佣金、查看业绩并申请提现。

### 2.2 参与角色

| 角色 | 主要需求 |
| --- | --- |
| 邀请人／合伙人 | 获取邀请链接和邀请码，查看邀请成果、佣金、等级，申请提现 |
| 被邀请人 | 经邀请注册或在符合条件时补填邀请码，领取并使用优惠券 |
| 运营及财务人员 | 开启或停用活动，处理提现，查询退款、佣金及异常记录 |

**参与资格已确认：所有用户都可以参加，不限学生身份，不做学生认证，不设置成为合伙人的人工申请或审批门槛。“校园合伙人”为活动名称，不构成人群限制。**

参与活动无需审批；提现仍须按第7节经过人工审核。异常或封禁账号的处置沿用独立的账号治理规则，具体权益处理见D01。

### 2.3 本期范围

1. 校园合伙人入口、活动介绍和合伙人中心。
2. 邀请链接、注册邀请码及未绑定用户补填。
3. 新人券领取、查看和按量充值使用。
4. 邀请消费累计、等级、佣金及退款处理。
5. 支付宝提现申请、处理和记录查询。
6. 新增校园合伙人独立邀请码、邀请关系、优惠券、业绩及现金佣金；旧邀请活动保持原有行为和数据，不自动迁移或联动。

### 2.4 不在本期范围

- 银行卡、微信提现。
- 群二维码及二维码占位。
- 修改已成功绑定的邀请人。
- 按新活动规则补发活动开启前已经完成首次可信成功结算的订单佣金。
- 新增多级下线佣金；本需求只描述直接绑定好友的消费返佣。

### 2.5 与现有生产功能的关系

| 现有能力 | 本次需求 |
| --- | --- |
| 现有账号、邮箱及OAuth登录注册 | 在既有流程增加邀请码确认及补填能力，保留原有注册和身份验证规则，不另建账号体系 |
| 旧“邀请好友”活动的邀请码、关系和链接 | 保持旧活动原样；校园合伙人使用独立邀请码、链接和绑定关系，旧码不能在新活动中绑定，不自动导入旧关系 |
| 旧邀请奖励额度及转余额功能 | 仅属于旧活动，保持原行为；新活动不读取其余额作为佣金、不兑换成现金、不因新绑定修改旧奖励或旧关系 |
| 现有充值下单、支付成功处理及到账 | 在原交易流程上增加活动券和返佣资格，不改变原充值到账额度、已付款订单价格或现有支付渠道行为 |
| 现有订阅购买与续费 | 代码具备站内余额购买／续费能力，但用户确认当前未开启，本次保持关闭；Plus／Ultra按实际套餐映射及外部实付判断，管理员免费赠送不计佣 |
| 现有后台用户、订单和权限管理 | 在其中增加佣金、退款登记及提现审核入口，复用现有管理员身份和权限体系 |
| 优惠券、现金佣金、支付宝提现 | 本次检查未在现有业务目录发现完整实现；按新增能力规划，不能假定已有优惠券中心或现金提现系统可直接复用 |

旧邀请活动、站内消费余额、新活动现金佣金分别处理。旧活动不受本功能影响；旧邀请关系不自动转成新活动关系，也不使用户自动获得或失去新活动奖励。历史已付费用户也可补绑一次；历史付款不追溯返佣。

### 2.6 生产增量接入约束

- 活动默认关闭。功能发布与活动开启分开，记录持久化的活动起点；未开启时既有充值、订阅和登录仍正常工作。
- 不清空、不重算现有用户余额、订阅权益和旧邀请额度，不修改旧邀请关系。新活动循环检查仅针对校园合伙人自身关系，不混入旧活动关系。
- 不修改套餐余额支付开关，不因活动开启而启用站内余额购买或续费月卡；活动返佣不将余额内部支付认作新增外部实付。
- 同一笔月卡购买在现有系统中可能同时留下订阅订单和充值汇总记录，必须按同一交易识别，不能重复计佣或计等级。
- **已确认：服务端支付成功通知与验签后的浏览器支付返回，均须核验成功支付及匹配订单，统一以订单首次可信成功结算时的有效绑定关系确定归属。同一真实交易跨通知入口、订阅订单与充值汇总记录，只计佣及计升级业绩一次。**单纯浏览器跳转不可信。人工补单仅在确认真实收款并关联原交易时参与，同交易仅计一次；管理员直接加余额不计佣、不计业绩。
- 普通页面跳转和前端声称支付成功不构成支付证明。新增返佣不能破坏原有支付验签、到账、续费及重试保证。
- 退款登记只调整合伙人佣金及业绩，不自动替代原支付退款、站内充值余额回收或订阅撤销流程；运营需分别确认实际订单退款已处理。
- **活动范围已确认：仅BeiAPI主站提供校园合伙人活动，主站现有beiapi.cn及www.beiapi.cn入口视为同一站点。Novapi、Dianapi及其他品牌站不参与。**
- 其他品牌站不展示活动导航、弹窗、补填、活动券或提现入口，也不能通过直接访问活动页面或接口进行本活动绑定、领券、用券、查询佣金或申请提现；不能仅隐藏菜单。
- 邀请链接统一指向主站活动入口，其他品牌站不生成自己的活动链接。共享账号或后端不意味着活动对其他品牌开放；在主站符合条件参与后，同一账号转到其他品牌也不能使用本活动权益。
- 仅主站来源、符合活动规则的订单计入本活动佣金和等级；其他品牌订单不计佣、不计业绩，不能使用本活动95折券。订单品牌以可信业务来源确认，不依据客户端可篡改参数或支付回调访问的域名认定。
- 主站产生的合法订单即使经统一支付回调入口确认，仍按主站订单处理；既有其他品牌充值、订阅和旧邀请活动保持原样。
- 历史成功支付记录不限制补绑；历史订单及已结算记录不得追溯返佣。

## 3. 核心业务概念

| 概念 | 定义 |
| --- | --- |
| 实付金额 | 用户使用优惠后，支付订单实际成功收取的人民币金额；不等于套餐显示的美元额度、充值到账额度或赠送额度。首版仅人民币实付参与，不进行外币汇率换算 |
| 合格订单 | 首次可信支付成功结算时已有有效邀请关系，且属于主站来源、首次可信支付成功结算时间在活动有效期间、商品符合活动范围的订单；停用及延迟确认边界见第 8 节 |
| 活动累计实付 | 用于判断等级的合格订单净实付金额合计；登记退款后扣减退款金额，等级可回退，规则见第7.1节 |
| 按量充值 | 可使用本活动 95 折券、按阶梯增量分段返佣的充值商品 |
| 月卡 | Plus 月卡和 Ultra 月卡，计入等级累计，分别按固定比例返佣 |
| 可提现佣金 | 当前允许申请提现的佣金，不包含已被提现申请占用的金额；佣金经过7天结算冻结期后可随时申请提现；统一于每月月底人工打款，具体时间边界见 D04 |
| 首次成功付费确认 | 系统首次完成账号的可信支付成功结算，包含按量充值及月卡；不影响未绑定账号的补填资格；每笔佣金从该订单首次可信支付成功结算时起冻结168小时，活动时间边界同样按该订单首次可信支付成功结算时间判断 |

## 4. 邀请与绑定

### 4.1 邀请人能力

- 用户能够获取本人的专属邀请码和邀请链接。
- 邀请链接使用主站实际业务域名及本活动专属入口，明确区别于旧“邀请好友”活动。旧码不得被新入口接受，新码不得误触发旧活动绑定和发奖。
- 用户能够复制邀请码或链接，复制成功和失败均有明确反馈。
- 邀请人能够查看自己的邀请记录；好友身份信息应脱敏。

### 4.2 绑定渠道

支持以下三条路径，绑定和新人券权益一致：

1. 好友打开专属邀请链接，注册时带入邀请码。
2. 好友在注册页面手动填写邀请码。
3. 已注册、未绑定的用户主动补填邀请码。

### 4.3 绑定规则

- **在校园合伙人活动内，每个账号最多绑定一位邀请人；邀请码提交并成功绑定后不可更换。后续手填其他邀请码或打开其他邀请链接，均不能覆盖已生效的邀请关系。**
- 不能绑定自己。
- **禁止形成循环邀请关系。**若A已邀请B，B不能再邀请A；若A邀请B、B邀请C，C也不能邀请A。任意长度的循环均不允许，注册绑定和登录后补填均适用；并发绑定也不得形成循环。
- **注册时邀请码非必填，不填写也能正常注册和登录。注册登录后可主动补填，只要账号尚未绑定。**
- 输入无效邀请码时，应提示更正或清空，不能把无效输入当作成功绑定。
- 邀请码有效时显示脱敏邀请人，供用户确认。
- 补填仅对未绑定的账号开放，成功绑定一次后禁用入口并显示已绑定原因。
- 未支付、支付失败和已取消订单不消耗补填资格。
- 历史支付或退款均不影响未绑定账号补填。
- 用户在确认补填前应知晓：绑定不可更换、不能绑定自己、历史付款不追溯返佣。
- 多次提交或同时提交不同邀请码，只能形成一个有效绑定结果，不得重复发券。
- **返佣归属已确认：以该订单首次可信支付成功结算时，账号是否已有成功生效的邀请关系为准。有有效绑定才给对应邀请人计佣、计业绩；输入框里填写但未成功提交不算绑定。**
- 用户实际付款后、首次可信支付成功结算前，若仍符合补填条件，可完成补填并领取优惠券，该笔付款也可计佣；这是有效绑定及发券，不作为误发处理。新领券不能反向修改已经实际支付订单的金额。
- 首次可信支付成功结算时，无论是否存在邀请关系，都记录该账号已成功付费，但不关闭未绑定账号的补填资格。没有有效绑定的订单不计佣，之后不因重复通知补发佣金。
- 补填与支付成功结算同时发生时，以系统最终生效顺序判定：补填先成功则按绑定计佣；首次可信支付成功结算先生效则该订单不计佣，之后仍可补填。不得既认定补填失败又发券，也不得重复绑定或发券。
- 订单首次结算时确定并保留邀请归属和结算结果；重复通知不重新认定归属，不重复计佣或计业绩。已有成功付费记录不限制补填，但已结算订单不会因补填而重新计佣。
- 活动起止资格、返佣归属及168小时冻结起点统一采用系统首次可信支付成功结算时间，绑定不要求早于实际付款时间。

### 4.4 注册与第三方登录

- 邀请码区域位于注册方式选择之前，适用于邮箱及现有第三方注册渠道。
- 原文涉及GitHub、LinuxDO；按实际站点当前启用的登录方式接入，保留验证码及协议确认能力，不因本活动启用某品牌站原本关闭的OAuth渠道。
- 用户经过第三方授权返回后，能够继续完成原邀请关系的确认与绑定。
- 第三方登录命中已有账号时，不视为新注册，不自动改绑，也不重复发券。
- 注册失败、授权取消或重复返回，不应造成错误绑定或重复领取权益。

## 5. 新人优惠券

### 5.1 已确认权益

- 邀请绑定成功后，向被邀请人发放 1 张 95 折充值券。
- **已确认：优惠券绑定领取账号，仅限该账号本人使用，不可转赠、转移或由其他账号代用。**
- 优惠券直接进入领取账号的“我的优惠券”，充值时由本人选择使用，不提供可供他人兑换的分享码。分享截图、券编号或链接不会转移券的归属，其他账号不能使用该券。
- 邀请码可以分享；优惠券本身不能分享使用。每个符合领取条件的被邀请账号分别获得自己的券。
- **已确认：本活动95折充值券永久不过期，但每张券只能成功使用一次；不是永久享受95折的折扣权益。**单笔优惠无上限。
- 仅适用于按量充值，不适用于 Plus 或 Ultra 月卡。
- 同一次绑定不得因重试等原因重复发券。
- 本活动已绑定用户不重复领券；旧“邀请好友”活动的绑定与奖励不等于本活动已绑定或已领券。旧活动用户只有符合本活动资格并独立绑定成功才领取本活动券。
- 券发放尚未完成时，用户应看到真实状态，不能显示已到账。

**用券细则已确认：不限首笔按量充值，不叠加其他折扣券；支付失败不消耗，支付成功后即核销，之后无论部分还是全额退款均不返券。95折后的实付金额四舍五入到人民币分，优惠金额为券前金额减实付金额。**例如券前¥10.10，95折后¥9.595，实际支付¥9.60，优惠¥0.50。

### 5.2 查看及使用体验

- 在现有钱包增加优惠券查看与使用入口，发放后可查看该券及适用范围；当前未确认存在可复用的优惠券中心，应按本期新增能力验收。
- 按量充值时可选择符合条件的券。
- 下单时同时显示券前金额、优惠金额和实际支付金额。
- 月卡下单不提供该券；绕过页面尝试使用也不能生效。
- 同一张券不能被多笔订单重复成功消费。
- 订单取消或支付失败，不应永久占用一张未成功使用的券；支付结果尚不明确时应保持一致的权益状态。
- 已成功支付订单的金额和优惠结果不可因刷新、重试或切换支付渠道而改变。

示例：原价 ¥200，使用 95 折券优惠 ¥10，实付 ¥190。该笔订单的佣金及等级计算基数均为 ¥190。

## 6. 等级及佣金

### 6.1 等级累计范围

- 累计所有直接绑定好友在活动开启后的主站合格订单实付金额。
- 包含按量充值、Plus 月卡和 Ultra 月卡。
- 活动开启前已经首次可信成功结算的订单不计入本活动等级累计，不因之后重试或通知重复而补计。
- **金额口径已确认：首版仅以订单实际人民币收款计佣和累计业绩，不按显示的美元额度或站内额度计算。**遇到实际非人民币收款订单不纳入本活动计佣及业绩，不直接按数值当人民币，不自行引入汇率换算；不影响该订单原有支付和到账。
- 免费赠送、管理员调额、兑换码和余额内部划转不生成本活动充值佣金。

## 7. 退款与提现

### 7.1 退款基线（已确认）

- 首版由运营在后台找到原订单，手动登记实际退款金额及原因，支持全额和部分退款；登记操作用于记录已处理的退款，不直接执行向付款人的资金转账。
- 确认前展示本次应扣回的原单佣金、即时扣减金额、新增退款待扣回佣金、等级累计及当前等级变化；确认后自动调整，保留原订单、退款和调整记录，不直接覆盖历史金额。
- 退款金额从邀请人的活动累计实付中扣减，按扣减后的累计重新判级，可能发生降级。Plus、Ultra月卡退款同样扣减等级累计。
- **降级只影响之后的新订单。其他正常历史订单在高等级期间已经产生的佣金保持不变，不追溯重算、不补扣差额。**
- **退款原订单对应佣金需要扣回，包括已实际打款的部分。已打款部分先扣当前可提现余额，不足部分记录为“退款待扣回佣金”，从后续解冻佣金中自动抵扣；不直接从支付宝扣款，不要求用户另行转账。**
- 原单佣金仍在7天冻结期时，扣减对应冻结佣金；已解冻尚未申请提现时，扣减对应可提现佣金；已申请但尚未打款时，暂停受影响申请，核对并调整后重新审核，不按旧金额直接出款。调整后不满足提现门槛的申请应取消并恢复剩余有效额度。
- 已实际打款的记录保持真实，不改写原提现金额或打款状态；新增关联原订单及退款的余额扣减及待扣回记录。原单部分已打款、部分未打款时，分别处理，防止重复扣减。
- 后续佣金仍按原规则经历168小时冻结，解冻时先用于抵扣退款待扣回佣金，剩余部分才进入可提现余额；抵扣流水需可查询，不改变该新订单的原始佣金计算结果。
- 用户侧分开展示“可提现佣金”和“退款待扣回佣金”，可提现金额最低为0。说明：“已提现的订单发生退款，相关佣金优先从可提现余额扣除，不足部分从后续解冻佣金中自动抵扣，无需另行转账。”不以“待抵扣限额”等模糊名称展示。
- 示例：需要扣回的已打款佣金为¥30、当前可提现余额为0时，显示退款待扣回佣金¥30；后续¥50佣金解冻后抵扣¥30，待扣回归零，可提现余额增加¥20。
- 若用户之后不再产生佣金，待扣回金额保留，不自动清零；本期不增加外部追款或自动扣款能力。
- **部分退款已确认：按累计退款金额占原订单实付金额的比例，计算累计应冲回原佣金；本次应冲回＝累计应冲回−此前已记账的冲回金额。**此前已记账冲回包含即时扣减及已记为待扣回的部分，不能因尚未收回而再次重复记账。累计应冲回佣金四舍五入到分后取本次差额，全额退款时累计应冲回恰好等于原佣金。
- 示例：原单实付¥200、佣金¥60，首次退款¥50应冲回¥15；再退款¥50时累计退款¥100、累计应冲回¥30，本次再冲回¥15。退完余下¥100后再冲回¥30，合计¥60。
- **抵扣顺序已确认：已提现订单退款先扣当前可提现余额，不足部分记退款待扣回佣金，由后续满168小时的解冻佣金继续抵扣；受影响的待打款申请暂停并重新审核。**不可提现的冻结佣金不提前解冻以用于抵扣，历史实际打款记录不改写。
- 不得用退款时的新等级重新计算原订单应冲回佣金。原单部分已打款、部分未打款时，应区分冲回总额和实际扣回来源，保证合计不重不漏。
- 全额退款应对原订单全部佣金完成冲回处理：未打款部分即时扣减，已打款部分先扣可提现余额，不足再记为退款待扣回佣金。重复登记同一退款不得重复扣佣金、增加待扣回金额或重复减少等级业绩。
- 成功支付及退款均不影响未绑定账号的补填资格。
- 已确认接受其他正常历史订单高等级收益保留带来的差异；本次扣回仅针对退款原单佣金，不自动重算其他订单。

### 7.2 提现基线

- **已确认：每笔佣金需经过7天结算冻结期，解冻后可随时申请提现；审核通过的申请由运营／财务在每月26日至月底手动转账，完成后在后台标记已打款。**
- **冻结起算已确认：以系统对该订单首次可信支付成功结算的时间为起点，满168小时解冻。**不按自然日计算，也不从实际付款时间起算；该时间首次确定后固定，重复通知、浏览器返回、返佣重试、后续重新入账或提现申请均不能重置冻结期。
- 例如11月1日15:30实际付款，系统15:35首次可信结算成功，对应佣金于11月8日15:35满168小时；发生退款或其他应扣减事项时按有效权益处理。
- 7天冻结期针对佣金结算，不是提交提现申请后再等待7天。冻结期内的佣金可以查看，但不可申请提现；解冻金额满足门槛后，不受月初、月中或月底限制。
- 产品展示“结算冻结中”“可提现”“提现处理中”“已打款”，区分佣金的7天结算冻结与提现申请对额度的占用，避免重复计算。
- 申请页面及申请成功提示应明确“审核通过后于每月26日至月底打款”，不能使用户误以为申请成功即到账。月底批次按第7.4节执行。
- 可提现金额满 ¥100 才可申请，单次申请最低 ¥100。
- 未申请提现的有效佣金余额自动结转至后续月份，长期保留，不因跨月清零；正常退款扣回及抵扣规则仍适用。
- 当前仅支持支付宝，需填写支付宝账号和真实姓名。
- 申请金额不超过当前可提现金额，最多两位小数。
- 可选择全部可提现金额，确认时应使用当前真实额度。
- 提交成功提示“申请已提交，等待审核；审核通过后于每月26日至月底打款”。审核通过后显示“审核通过，待月底打款”；只有实际手动转账完成并由授权人员标记后，才显示“已打款”。
- 已被申请占用的金额不可再次提现。
- 用户可查看申请时间、金额、脱敏收款账号、处理状态及失败或拒绝原因。
- 审核未通过或确认打款失败后，应恢复相应权益；成功打款只扣减一次。
- 手动转账结果尚不能确认时，应保留待打款或待核实状态，核对实际转账结果后再标记；不能误报失败并允许重复提取同一笔资金。
- 关闭弹窗不会创建申请，提交失败应保留输入并告知原因。
- 收款账号和姓名只对本人及必要的授权处理人员可见，普通记录展示脱敏。

### 7.3 运营处理能力

- 授权人员能够查看、审核、拒绝和处理提现申请。
- 审核通过后，运营／财务在每月26日至月底手动完成支付宝转账，再对对应申请执行“标记已打款”。
- 标记时记录实际转账时间及转账流水号或凭证，并保留操作人员和标记时间，便于对账。审核通过本身不能代替打款标记。
- 能够查询审核结果、拒绝原因、打款结果和凭证，追踪操作过程。
- 重复处理同一申请不能造成重复打款。
- 本期采用人工转账，不建设自动出款能力。
- 主流程为：佣金产生 → 7天结算冻结 → 解冻为可提现 → 用户随时申请 → 待审核 → 审核通过／待月底打款 → 月底人工转账 → 标记已打款；审核拒绝的理由选填，并恢复相应可用额度。

### 异常提现处理（已确认）

- 对发现异常的提现申请暂停处理并展示原因，暂停期间不得打款；保留账号现有余额、申请及全部流水，不以异常为由直接清零或删除。
- 人工核查后恢复正常审核和批次处理，或在确有退款时按第7.1节登记退款和调整，记录操作人员、原因与处理结果。
- 已被暂停申请占用的金额不可再次提取；恢复后进入可用的后续批次，更新预计打款月份，不重新计算原佣金168小时冻结期。
- 本活动不另建学生身份门槛或自动没收权益规则；账户登录、封禁等继续遵循现有账号管理能力。

### 7.4 月底打款批次（已确认）

- 统一按北京时间（Asia/Shanghai）划分申请批次。
- **每月26日至月底人工打款，不因周末、法定节假日或其他休息日顺延至工作日。**
- 每月25日结束前提交的申请归入当月批次，即申请时间早于当月26日00:00:00；审核通过后于当月26日至月底人工打款。
- 每月26日00:00:00起仍可随时申请，归入下月月底批次。批次按申请时间确定，不因提早审核而自动提前打款。
- 运营应在对应月底打款前完成审核；执行批次时仍未完成审核的申请保留原单顺延至下月，展示原因及下一预计打款月份，不要求用户重新申请，不重新计算7天冻结期。
- 明确审核拒绝的申请不进入顺延队列，理由选填，并恢复相应可提现额度。
- 申请确认页、申请成功页及提现记录均显示预计打款月份；审核或批次变化时同步更新。预计月份以审核通过为前提，不能将申请成功展示为已打款。
- 审核超时作为运营异常跟进，不能无限期无说明顺延；月底打款不考虑休息日，仍未完成审核的申请按上述审核顺延规则处理。
- 示例：11月25日23:59提交并审核通过，11月底打款；11月26日00:00提交，归12月底批次；11月批次执行时仍未完成审核，原单顺延至12月并说明原因。

### 9.2 合伙人中心

1. 活动标题、当前等级及规则说明。
2. 始终展示补绑邀请码入口；不符合资格时禁用并说明原因。
3. 本人邀请码、邀请链接、复制操作和好友优惠说明。
4. 结算冻结中佣金（7天）、可提现佣金、累计佣金、已提现、提现处理中金额及退款待扣回佣金。累计佣金显示收入减退款冲回后的净额；提现及实际抵扣只是资金流转，不再次减少累计净佣金。明细保留原收入、退款冲回及抵扣，避免重复扣减。
5. 邀请人数、本月新增人数及活动累计实付。本月新增按本活动绑定成功时间统计，所有统计日期及月份统一使用北京时间（Asia/Shanghai）。
6. 等级区间、当前比例、距下一档金额和进度；最高等级不再显示升级差额。
7. 邀请记录、佣金明细、提现记录，支持分页、加载、空状态及失败重试。

“活动累计实付”旁应说明包含按量充值和两种月卡，且仅统计活动开启后的合格实付。不能将其误写为仅按量充值的累计。

### 9.3 活动提醒

- 登录进入控制台后，可展示活动介绍及“获取我的邀请码”入口。
- 内容读取当前按量阶梯和套餐返佣配置，并说明好友95折券；不写死最高比例。
- 主按钮进入合伙人中心；关闭或稍后再说不产生参与、绑定或提现行为。
- 不遮挡支付回调等关键流程，不与其他重要弹窗叠加。
- 不加入群二维码、虚构倒计时和未经确定的截止日期。
- 每个账号按北京时间每天最多自动展示一次，刷新或更换设备不重复展示；点击“获取我的邀请码”后，本活动版本不再自动弹，常驻入口仍可访问。
- 关闭只关闭当前弹窗，当天不再自动展示，之后未点主按钮的账号按每日上限处理。活动停用不展示招募弹窗；重新开启同一活动版本不重置已点击主按钮的状态。

### 9.4 通用体验与权限

- 邀请码提供空、校验中、有效、无效和暂时无法校验等状态；快速修改后不显示旧码对应的邀请人。
- 桌面、平板和手机均可完成注册、补填、查看记录及提现；320px 宽度下页面主体不横向溢出。
- 长列表或宽表格可在自身区域滚动，弹窗内容可滚动且关闭按钮可见。

- 用户只能查看自己的佣金、邀请和提现信息，不能修改他人的关系、金额或记录。

### 已确认的退款收益示例

按已确认规则（示例中的退款原单佣金尚未打款）：先按量充值 ¥2,000，佣金 ¥600；再充值 ¥8,000，佣金 ¥2,800；全退第一笔并冲回 ¥600。最终净实付 ¥8,000，保留佣金 ¥2,800。若直接从零充值 ¥8,000，则佣金为 ¥2,700。

已确认接受这¥100的差异，其他正常历史订单不重算。若退款原单佣金已实际打款，该部分先扣当前可提现余额，不足再记为退款待扣回佣金并从后续解冻佣金中抵扣；退款金额仍扣减升级业绩，后续新订单按回退后的等级计算。
