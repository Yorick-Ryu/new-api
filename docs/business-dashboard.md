# 管理员经营看板

入口：`/business`（管理员 → 经营概览，位于系统信息上方）。首页和数据看板不再展示；原地址 `/dashboard/business` 自动跳转到新页面。
接口：`GET /api/data/business?days=1|3|7|30|90&offset=0|1`，使用 `AdminAuth`，响应不允许缓存。页面默认今天，提供昨天、近 3/7/30 天，以及与模型分析同样控件的时间筛选弹窗。自定义查询使用 `start_timestamp` 与 `end_timestamp`（秒），不能与 `days/offset` 混用；范围为左闭右开、不可晚于当前时间，跨度最多 30 天。

- 按北京时间自然日统计，包含今天；昨天为 `days=1&offset=1`。快捷范围的环比为前一个同天数周期的相同时刻；自定义范围对比紧邻的前一段等时长区间。成功订单按创建时间归属（包括未记录完成时间的历史充值），趋势始终按北京时间自然日分桶。
- 新用户充值率：本期注册且本期成功充值人数 / 本期注册人数。
- 新用户充值金额下的人均充值：本期新用户充值金额 / 本期充值的新用户数，金额仍按渠道分别展示；无充值新用户时显示“—”。
- 充值仅含成功的钱包充值，按订单号排除套餐镜像记录；兑换码、赠送和余额消费不计入。
- 易支付金额为 CNY；其他渠道展示订单原始单位，分别汇总，不与人民币混加。
- 套餐新购（含余额支付）、续费、管理员赠送分别统计。
- 历史注册统计保留软删除用户，最近列表只返回必要展示字段。

验证：`go test ./model ./controller ./router`；前端运行 business 模块的 Vitest、typecheck、lint 与构建。

- 总收入包含易支付的钱包充值与直接套餐支付，排除余额支付及套餐充值镜像；无法确认现金计量单位的其他渠道仅提示订单数，不混加。
- 首次付费以钱包与套餐两类订单中最早的成功外部支付为准；活跃用户从独立 LOG_DB 的保留消费日志去重，日志不可用时显示缺失。
- 有效套餐与未来 7 天到期数为当前快照。续费率按本期到期的套餐周期计算，每次续费交易保存原套餐 ID 和原到期时间，早续与晚续均归属原到期周期；统计截至所选周期末。
- 迁移使用不可变的 `BusinessRenewalTrackingStartedAt` 标记可靠记录的起点；更早历史不可还原时在接口标记不完整，不伪造历史续费率。

- 单张趋势图每个日期从左到右依次展示新增用户、当前启用套餐的新购与续费堆叠、充值与套餐现金收入堆叠；不展示充值订单数（数量左轴，金额右轴）；每日收入合计与总收入一致，套餐数量包含余额购买。

- 套餐卡片与趋势系列由当前启用的套餐目录生成，按套餐 ID 归属订单；改名不影响统计，停用或删除的套餐不展示，新增套餐即使无订单也展示零值。历史总收入仍包含停用套餐的支付。
- 各套餐卡片同一行依次展示新购数、续费数，下方显示两者合计较上期的数量增减，沿用相同时长和截止时刻的对比窗口；页面不展示续费率及其历史完整性说明。

- 趋势与模型调用分析共用 VChart、默认配色、原生提示框与切换控件样式。悬浮时以灰色背景高亮整组日期，柱状图悬浮单个色块显示该指标，上方空白区域显示当日汇总；面积图使用不堆叠的平滑曲线与 0.08 透明度填充。数量与人民币金额分别使用左右轴，提示框仅合计现金收入，不跨单位相加。

- 客单价位于当前有效套餐之前，套餐收入位于套餐卡片之前。套餐收入仅计成功的易支付直接套餐支付（含新购及续费）；客单价为总收入 / 同期易支付外部支付的去重用户数，跨钱包和套餐合并去重，无付费用户时显示“—”。两项沿用本期及上期时间窗口，不计余额购买、赠送或其他渠道金额。
