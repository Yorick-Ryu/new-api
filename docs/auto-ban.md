# 自动封禁

入口：系统设置 → 安全与限制 → 自动封禁。普通管理员和超级管理员可以查看、修改和测试规则；普通用户不能访问相关管理接口。

- 默认关闭，可切换为「仅记录」或「自动禁用账号」。管理员账号命中规则只记日志。
- 以规则列表管理，每条规则独立设置名称、启用状态、封禁原因及匹配条件。编辑后先应用到页面草稿，再从页面顶部保存生效。
- 每条规则可设置多组匹配条件，组内条件全部满足才算命中，组间满足任意一组即可；任意启用规则命中即可处理。可按渠道 ID、模型名称限定范围，留空表示全部。配置只使用 `match_groups` 结构，不保留未发布版本的转换逻辑。
- 匹配字段为原始 HTTP 状态、上游错误码、错误消息、安全违规类别。禁止只根据 HTTP 状态封号。正常回答、拒绝文本和用户提示词不参与匹配。
- 预置色情类安全拒绝、内容安全拒绝、网络安全三条规则。「网络安全」包含风险文案与 `cyber_policy` 错误码两种匹配方式，任意一种满足即可命中，同一错误同时满足两种方式仍只命中这一条规则。支持普通 HTTP 错误、HTTP 200 流式错误和 Responses WebSocket 错误（包括握手失败）。
- 自动模式下一次命中即禁用整个账号，阻止后续 HTTP 令牌请求及新建 WebSocket 连接，停止当前错误的渠道重试，不因此自动禁用渠道。已在途的其他请求不强制中断；已建立的 WebSocket 连接不因账号封禁而主动断开，后续轮次仍可继续，断开重连时才重新鉴权。
- **没有自动到期或封禁时长**：账号持续禁用，直到管理员在封禁记录右侧点击「解除封禁」，或在用户管理中手动启用。修改规则或关闭自动封禁不会自动解封历史账号，也不会重放历史报错。

检测入口只位于实际错误分支：普通 HTTP 错误在统一错误处理器中检测；HTTP 200 的 OpenAI/Responses/Claude 错误复用已有响应解析；Responses SSE 与 WebSocket 根据已解析的错误事件类型检测。通用流式扫描器不执行自动封禁检测，正常成功响应不为本功能扫描、复制或重复解析正文，也不读取规则。WebSocket 仅在连接建立时通过现有 TokenAuth 检查账号状态，每轮不额外查询账号状态；每轮仍重置自动封禁事件标识和重试标记，保证不同轮次的错误分别记录。

规则保存在主数据库 `options` 的 `AutoBanSettings` 项。每次实际上游失败时读取已保存配置，各实例无需重启即可使用新规则。保存时检查版本，过期编辑返回 HTTP 409，避免覆盖其他管理员的修改。

记录列表中的「命中规则快照」为带下划线的文字入口，请求信息与当时保存的规则、匹配条件集中在详情弹窗中。右侧「解除封禁」复用 `/api/user/manage` 的 `enable` 操作及权限校验，记录管理日志；成功后显示「已解封」，保留原封禁记录。当前账号状态仅在查询记录列表时批量读取，不增加正常转发请求的开销。

命中记录保存在主数据库 `auto_ban_events`，与禁用账号在同一事务提交；记录用户、请求、渠道、模型、处理结果和命中规则版本及快照，不保存提示词、密钥或完整上游报文。同一请求与规则版本去重，手动解封后重复处理旧事件不会再次封号。

管理接口（均需管理员认证）：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET / PUT | `/api/auto-ban/` | 读取 / 保存配置 |
| POST | `/api/auto-ban/test` | 使用草稿和错误样例试匹配，不保存、不封号 |
| GET | `/api/auto-ban/events?before=<id>` | 按 ID 倒序分页查询记录 |

验证：`go test ./setting/auto_ban ./model ./service ./controller ./relay/helper ./relay/channel/openai ./relay ./router`；前端在 `web` 下运行 `bun run typecheck`、涉及文件的 lint 和 `bun run build`，在本地预览检查交互；不新增 UI 自动化测试。涉及封禁并发或缓存修改时，再运行 `go test -race ./model ./service ./relay/helper ./relay -run AutoBan`。
